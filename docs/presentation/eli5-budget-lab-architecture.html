Copilot Budget Lab · how it's built

One simulator, two cockpits, and an agent that writes its own homework

A tour of the standalone app, the GitHub Copilot Desktop canvas, and the cloud agents that generate its scenarios.

0

Think of it as a flight simulator for your GitHub bill

Same instruments, same simulation engine — only the co-pilot answering your questions changes seats.

1

It runs two completely different ways

Top: npm start → server.js, fully offline. Bottom: the same app opened as a Copilot Desktop canvas.

2

Standalone mode is a deterministic replay machine

JSON scenarios feed engine.js, which replays every event deterministically for app.js to render — nothing calls out to an AI model here.

3

The canvas app quietly stands up its own loopback server

The canvas extension re-serves the exact same static app, plus one new route: /api/assistant, restricted to loopback traffic only.

4

The embedded co-pilot is the real, live Copilot session

There is no separate model call: the question rides into the same Copilot session that opened the canvas, scoped by a mandatory skill.

5

Even the scenarios were written by agents, not by hand

The two agents ask clarifying questions first, then write declarative JSON that npm test checks before it ever reaches the engine.

Same deterministic engine, everywhere — only the co-pilot's brain and the data's author change.

Gotcha: the copilot backend only activates when the canvas explicitly sets assistantBackend: "copilot"; plain npm start never talks to any AI model.

Copilot Budget Lab · the cost-control model

Your GitHub AI bill isn't one meter — it's a stack of independent shutoff valves

Why cost centers, pools, and budgets feel complicated: every usage event is checked against several controls, in a fixed order, before it's allowed.

0

It's a water system with tanks inside tanks, plus a meter on every tap

The big tank feeds a smaller cost-center tank, and every user still has their own meter that can shut off — regardless of what's left in either tank.

1

Money flows down a fixed org hierarchy

A user's cost center comes from direct assignment first, then enterprise-team membership, then their license-granting organization — in that order.

2

One shared pool of included AI credits, refilled monthly

Every seat contributes its included credits into one enterprise pool that all AI usage draws down before anything counts as paid.

3

A cost center can carve its own tank out of that pool

Once a cost center's own pool cap is hit, its configured behavior decides everything: hard-block, or spill into paid overage.

4

The per-user meter is checked first, and it never bends

Whichever ULB level applies wins in this order: the individual's own budget beats the cost-center one, which beats the universal one — and it always blocks.

5

Above the pool, three more budgets watch only the paid part

These only ever measure paid overage after the included pool is gone — and each is independently configured.

6

Every single usage event runs the same gauntlet, in order

This is the app's own "Why this state?" explanation order — the same four checks, every time, for every event.

It isn't one number to watch — it's four independent valves, checked in the same fixed order, every single time.

Gotcha: only the user-level budget and the exhausted pool cap are true hard stops by default; the org/enterprise/cost-center spending budgets only bite if someone turned "stop usage" on.

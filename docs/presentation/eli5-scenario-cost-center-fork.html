Events are atomic: a 200-credit request that would cross the 100-credit cap is rejected in full, not trimmed to fit.

3

Branch B — "allowOverage": the pool fills, then the tab opens

2,400 credits × $0.01 = $24.00, which is 80% of the cost center's own $30 metered-overage cap — crossing its 75% threshold alert.

4

Side by side: identical request, opposite books

Nothing about Alice's request changed — only the cost center's own included-pool cap policy decided the outcome.

The pool cap doesn't ask "how much is left?" — it asks "block, or bill?" and that answer is set once, per cost center.

Gotcha: in overage mode the cost-center's own metered budget can still hard-stop later swipes once it's exhausted — the pool cap and the metered budget are two separate valves, not one.
